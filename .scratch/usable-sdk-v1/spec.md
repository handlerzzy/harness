# 第一版可用 Python SDK

Status: ready-for-agent

## Problem Statement

作为希望在 Python 程序中使用 Agent 的开发者，用户已经有一个具备 Agent 循环、工具调度、流式事件、Session、持久化、摘要和执行环境的项目，但安装后仍不能直接接入真实模型完成任务。当前示例依赖模拟回复，真实模型协议转换、内置编码工具及各层组装仍需使用者自行完成。

用户希望获得一个可以实际嵌入应用的 SDK：配置模型后即可运行多轮任务、观察过程、执行工具、取消操作、保存并继续对话。Pi 提供参考架构和实现经验，本项目应按实际需要取舍字段、模块和服务，而不承担全量一比一移植或兼容所有上游接口的目标。

## Solution

交付面向本地 Python 应用的首版 SDK：以统一模型协议连接 Agent 与底层 API，首先实现 OpenAI Chat Completions 适配器，接通已有 Agent/Harness，提供 read、write、edit、bash 工具、Session 保存与继续、上下文压缩，以及可直接运行的示例和文档。

用户可以显式配置模型服务、工作目录和会话，通过简洁的公开入口提交任务、订阅事件、取得最终结果及取消执行。核心链路只依赖文本、工具调用与结果、结束状态、错误和取消；thinking、usage 和厂商扩展信息为可选能力。

首版完成后，SDK 应能在临时项目中读取一个有简单错误的文件，修改代码，执行验证命令，根据工具结果继续处理并给出符合实际结果的结论；重新打开已保存的 Session 后能够继续提问。

## Implementation Decisions

1. **参考架构与兼容目标。** Pi 的分层、协议和源码是参考，固定的 0.80.10 快照提供可复查依据。按本项目需求精简字段、模块和服务，不要求完整上游兼容，也不以跟进最新版为前提。优先复用已有实现；确有必要改变现有公开 API 时说明变化和迁移方式。
2. **首版应用边界。** 面向本地 Python 程序，提供 SDK 和简单命令行示例。首版验证以 Linux 为基线，沿用当前 Python 版本支持声明与 CI 矩阵。
3. **统一模型协议。** 统一上下文、消息、文本、工具声明、工具调用、工具结果、模型事件和最终结果。必要信息包括消息角色、内容类型、调用标识、工具名称、参数、结果归属、结束状态与错误；不机械保留所有上游字段。
4. **必需与可选能力。** 文本、工具调用及结果、结束状态、错误和取消是核心；thinking、usage 与厂商扩展为可选。可选信息缺省不影响核心流程，不伪造缺失内容，不把未知用量当作真实零用量。
5. **API 适配边界。** 首版仅实现 Chat Completions。适配器负责统一请求到 API 负载的转换，以及原始流到统一模型事件和结果的转换。未来其他 API 可通过新适配器遵守同一内部契约，Agent 循环不依赖供应商原始响应格式。
6. **模型配置。** 接受显式 key、base URL、模型标识、上下文窗口、输出限制及必要调用选项。使用轻量配置，不引入完整模型注册、远程目录或自动发现服务。凭据由调用环境提供，不保存到 Session。
7. **流式语义。** 模型事件可表达开始、文本增量、工具调用增量、可选 thinking 及终态。增量与累计消息语义明确，最终结果与事件一致；不同服务不必具有相同切块或事件数量。请求建立失败可以直接失败，不强制先发开始事件。
8. **终止保证。** 每次模型调用最终归结为一个明确结果；成功、错误、取消和无合法终态的断流都要结算事件流与最终结果等待。区分正常停止、长度限制、工具调用、失败和取消。长度截断或无法完成解析的工具参数不得触发真实工具执行。
9. **工具参数和结果。** 用调用标识正确关联多个及交错工具调用，完成参数重建和校验后才交给工具执行。历史中的工具调用和结果转换回底层请求时保持匹配。
10. **统一访问方式。** 以简化的模型访问层连接现有流函数与 Harness 所需的流式/一次性完成能力。一次性完成复用同一模型流的最终结果，供摘要及分支摘要使用，不建立第二套协议实现。
11. **Agent 与 Harness。** 将真实适配器接入已有循环、事件、hooks 和队列。提供简洁的公开组装入口，接受模型、工作目录、Session、工具和显式资源；调用者无需实现内部协议转换。
12. **会话架构。** 优先延续本项目已有的 Harness/Session 路径。Pi 中另有 coding-agent 的独立会话协调层；借鉴其组件时明确适配，避免混合两套生命周期。
13. **事件分层。** 模型事件描述响应生成，Agent 事件描述轮次、消息和工具执行。模型产生工具调用不代表工具已执行；订阅者应能观察两者及最终状态。
14. **内置和自定义工具。** 提供 read、write、edit、bash 和现有参数约束/自定义工具契约，基于已有执行环境与输出组件实现。工具错误可反馈给模型；edit 缺失或歧义匹配时失败且不写入。shell 返回输出与退出码，支持超时和取消；长输出截断时提供完整输出位置。
15. **失败与重试。** 明确区分请求失败、工具失败和用户取消。瞬时请求失败可有限重试；重试范围不得跨越已执行的工具而重跑整轮任务。取消不触发重试，配置错误不进行无意义重试。具体次数和等待值由实现选择有界默认值并文档化。
16. **Session。** 复用内存与 JSONL 存储，保存对话、工具调用和结果，支持显式新建、打开和继续。保留已有树形能力。继续会话指恢复历史后继续提问；不保证崩溃后自动接续或重放未完成执行。
17. **上下文压缩。** 复用现有 token 估算、切分与摘要能力，接入手动及阈值自动压缩。模型上下文限制必须显式可用，usage 不足时使用标明的估算。压缩安排在模型请求前或已完成一轮交互的安全边界，不破坏工具调用/结果关系；更新后的持久化上下文用于后续请求。失败或仍超限时给出明确结果，避免无限重试。
18. **资源接入。** 接受 system prompt、工作目录、自定义工具和显式指定的 skills/提示模板，优先复用现有加载与调用能力。无需建设完整的隐式配置搜索、继承和热重载体系。
19. **代理修复。** 保留现有代理能力并修复已复现的提前 EOF 不结算问题；其终止保证与直接适配器一致。此项不扩展为建设代理服务端。
20. **交付与文档。** 提供真实任务 Python 示例、简单命令行示例，以及安装、模型配置、订阅事件、工具扩展、取消、Session 继续和压缩说明。构建产物需在独立环境验证可安装和可导入。

## Testing Decisions

1. **已确认的主测试边界。** 用户已确认以公开 SDK/Harness 入口作为主行为边界，通过可控 Chat Completions HTTP 响应驱动模型、真实工具和真实 Session 的完整链路。对 SDK 调用结果、可观察事件、后续 HTTP 请求内容、临时目录文件及重新打开的 Session 作断言。
2. **尽量只替换外部模型服务。** HTTP 客户端/transport 是主链路中的外部替换点，沿用现有可注入 HTTP 客户端和 MockTransport/分块响应的做法。直接适配器复用这一边界；不为解析器、组装器、工具注册器或存储内部方法新增测试专用抽象。
3. **高层测试优先。** 模型访问、Agent/Harness、四个内置工具、Session、压缩和公开入口优先在同一公开链路覆盖。现有低层测试继续保留；只对无法从高层清楚定位且有实际风险的协议边界补充公开适配器测试。
4. **什么是好测试。** 测试用户能观察的行为和契约，断言结果、持久化、实际副作用、错误分类以及必要事件顺序。不对私有方法、内部类结构、偶然调用次数、原始 chunk 数量或供应商自然语言答案作脆弱断言。
5. **完整任务。** 可控模型先请求读取临时文件，再修改并执行验证命令，最后消费工具结果结束。覆盖多轮请求以及多个工具调用，检查后续请求携带正确结果、文件内容和命令结果确实变化，而不仅检查最终文本。
6. **适配器请求与流。** 在同一 HTTP 边界验证 system/history/tools/result 转换、分块 UTF-8、文本与工具参数片段、多个交错调用、合法结束、长度限制、错误状态、usage 缺省和可选字段。对等价 chunk 切分断言等价的统一结果与事件语义，不要求增量数量相同。
7. **错误结算。** 覆盖错误凭据、HTTP 失败、超时、无终态 EOF、参数 JSON 无法完成以及开始前/开始后的取消；用有界等待确认最终结果和订阅均可结束，且未就绪工具没有执行。
8. **工具副作用与重试。** 使用真实临时文件和受控本地 shell，验证 read/write/edit/bash、匹配歧义不改文件、非零退出码、截断与完整输出、超时和进程取消。请求重试后验证文件或命令副作用不被重复，取消后无新请求/工具执行。
9. **Session 继续。** 用公开保存/打开方式跨实例及新进程验证历史与工具结果完整，并通过后续模型请求证明恢复内容真正进入上下文。已有分支与 JSONL 回归测试继续覆盖存储契约。
10. **压缩。** 用显式小上下文限制、可控摘要响应和必要时缺省的 usage 触发手动/自动压缩。断言摘要记录可保存、近期必要消息与工具关系有效、后续请求实际使用压缩上下文，并覆盖摘要失败与压缩后仍超限的明确结束。
11. **现有先例。** 沿用 Agent/loop 的事件与工具顺序测试、Harness 的模拟模型/hooks/保存点测试、代理的 MockTransport/分块 SSE/取消测试、执行环境的真实临时文件及 subprocess 测试、Session 仓库的 JSONL 重开与分叉测试，以及摘要的 token 估算和生成失败测试。新主链路把这些已有边界组合起来，不重复建设另一套测试框架。
12. **真实服务验收。** 另设显式选择的真实 Chat Completions 验收，连接运行环境指定的 endpoint/model，完成读取、修改、执行验证和根据结果继续的任务。以文件和验证命令结果判定成功，不断言固定模型措辞；普通测试无需凭据或付费请求。
13. **打包与回归。** 完成现有测试、严格类型、格式和 lint 检查，按当前 Python CI 矩阵回归；构建 wheel 后在独立环境安装、导入并执行最小公开用例。文档修改本身仅验证结构、链接和规格一致性，不声称本轮完成业务代码验收。

## Out of Scope

- 其他 API 协议的实现及所有 Chat Completions 兼容厂商扩展的完整覆盖。
- 与 Pi 所有字段、接口、默认行为、模块目录或新版架构的一比一兼容。
- 完整模型目录、自动发现、价格表和费用计算服务。
- OAuth、完整 TUI、MCP、RPC 服务、插件包管理、隐式配置继承和热重载体系。
- 图像、音频及其他多模态任务的首版验收。
- 远程部署服务、多租户调度、权限管理服务和服务端代理建设。
- durable 崩溃恢复、自动接续或重放中断工具、跨进程并发写同一 Session 的协调服务。
- 无上限重试、全厂商上下文溢出自动修复、额外的运行预算或成本控制体系。
- 为满足逐字段上游兼容而额外引入不服务本 SDK 目标的字段、模块或服务。

## Further Notes

- 本规格发布到项目约定的本地 issue tracker，并按用户调用 to-spec 的要求标记为 ready-for-agent；不进行额外访谈或重复 triage。
