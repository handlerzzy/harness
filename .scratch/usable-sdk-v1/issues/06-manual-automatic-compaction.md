# 06: 手动与自动压缩上下文后继续任务

**What to build:** 使用者能够主动压缩已保存会话，也能在上下文接近显式模型限制时自动压缩并继续任务。摘要、保留消息和工具关系形成有效的新上下文；摘要失败或压缩后仍超限时明确结束。

**Blocked by:** 05：创建、保存并继续带资源的 Session。

**Status:** ready-for-agent

**Upstream reference:** 开始实现前，按[固定上游参照与本票模块映射](../../../UPSTREAM.md#sdk-implementation-reference)阅读对应源码及行为测试，并在 Comments 记录参照来源和必要取舍。

**Spec coverage:** 4, 39-42, 46-47.

- [ ] 手动压缩通过统一模型访问层生成摘要，一次性摘要调用复用流式最终结果；复用已有 token 估算、切分和摘要能力。
- [ ] 使用显式上下文窗口和输出限制确定有效输入预算；自动压缩阈值、保留策略等具体默认值有界、清楚且有文档说明。
- [ ] usage 可用时按其语义使用，缺少时使用明确标明的估算；未知 usage 不按真实零用量处理，也不能导致完全跳过上下文管理。
- [ ] 自动压缩发生在模型请求前或已完成交互的安全边界，不拆开必须成对保留的工具调用和结果，也不通过调用仅允许 idle 的接口破坏运行状态。
- [ ] 手动与自动压缩均保存摘要记录及必要元数据；后续请求和重新打开的 Session 实际使用压缩上下文，近期必要消息及工具关联有效。
- [ ] 摘要请求失败或压缩后仍无法满足上下文限制时，公开调用和事件给出明确结局；不会反复压缩、无限重试或发送已知仍超限的请求。
- [ ] 使用公开 SDK/Harness、真实 JSONL Session、显式小上下文和可控摘要 HTTP 响应，分别触发手动和自动压缩；检查实际后续请求与重新打开后的上下文。
- [ ] 同一边界覆盖缺省 usage、工具交互后的压缩、摘要失败和压缩后仍超限；沿用现有切分、估算、分支摘要与生成失败回归测试。
- [ ] 文档说明调用方式、自动触发条件、估算依据、默认值及失败处理，保持当前公开手动压缩能力可用。
