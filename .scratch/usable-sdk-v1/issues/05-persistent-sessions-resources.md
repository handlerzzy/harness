# 05: 创建、保存并继续带资源的 Session

**What to build:** 开发者通过公开入口选择内存或 JSONL Session，显式传入 skills 和提示模板，完成任务后在新进程打开历史继续提问。会话继续恢复对话依据，不自动接续或重放中断工具。

**Blocked by:** 02：通过自定义工具完成多轮 Agent 任务。

**Status:** ready-for-agent

**Upstream reference:** 开始实现前，按[固定上游参照与本票模块映射](../../../UPSTREAM.md#sdk-implementation-reference)阅读对应源码及行为测试，并在 Comments 记录参照来源和必要取舍。

**Spec coverage:** 5, 34-38, 43, 45-47.

- [ ] 公开入口支持显式新建内存或 JSONL Session，以及打开已保存的 Session；可与模型、system prompt、工作目录和自定义工具共同配置。
- [ ] 对话、工具调用、工具结果和必要的相关配置历史沿用现有存储能力保存；API key 等凭据不写入 Session。
- [ ] 跨实例及新进程打开 Session 后，后续 HTTP 请求实际携带恢复的历史和正确匹配的工具结果，不仅验证 JSONL 能被读取。
- [ ] 中断或失败的执行不会被记录为成功或在重开时自动重放；已保存历史可供判断后继续提问，不承诺 durable 执行恢复。
- [ ] 保留已有树形 Session、分支和 JSONL 存储契约，公开组装入口沿用已有 Harness/Session 生命周期，不另建一套会话协调层。
- [ ] 显式传入 skills 和提示模板后，可通过现有调用能力执行实际对话任务；验证资源内容或模板参数确实影响模型请求。
- [ ] 资源接入复用已有加载能力；本票不扩展隐式配置继承、自动发现和热重载，资源选择由调用者明确提供。
- [ ] 主测试使用真实内存/JSONL Session、临时目录、真实自定义工具与可控 HTTP；包含新进程重开，并保留现有仓库、分支和资源测试。
- [ ] 提供新建、保存、显式打开、继续对话及资源注入的使用说明，说明凭据来源与会话历史恢复的边界。
